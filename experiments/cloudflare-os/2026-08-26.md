# Cloudflare OS experiment — 2026-08-26

## Goal

Deploy Cloudflare OS, understand its architecture, create a first Gadget, and probe model/runtime behavior.

## Deployment observations

The hosted deployment created multiple Workers and connected services rather than a single monolithic app.

Observed components included:

- router / frontend Worker
- backend Worker
- Context Gatekeeper Worker
- Scheduler Gatekeeper Worker
- Durable Object-backed state
- KV / R2 bindings
- Workers AI binding
- AI Gateway
- Cloudflare Access application

The backend is deployed as a large bundled `server.js`; this is a build artifact rather than the original source layout.

## Architecture learned

### Durable Object

Useful mental model:

```text
actor + persistent storage + coordination point + serverless lifecycle
```

Cloudflare OS uses Durable Objects heavily for workspace and application state.

### Gadget

A private application instance owned by a user. It combines code, runtime, state, and an agent-friendly API.

### Blueprint

A reusable application template / code snapshot used to instantiate a new Gadget. Rough analogy:

```text
Blueprint → Gadget
executable → process
image → container
```

### Gatekeeper

Capability-oriented boundary between an agent/Gadget and an external resource or privileged system function.

Observed default Gatekeepers:

- Context — search/list/read knowledge collections
- Scheduler — persistent future callbacks / schedules

## Authentication failure mode

At one point the UI loaded but the top-right indicator remained:

```text
Reconnecting…
```

No agents/models appeared and messages did not progress.

Re-authenticating Cloudflare Access fixed the issue immediately.

Interpretation: static frontend assets can remain usable while the authenticated backend RPC/WebSocket control channel is unavailable. This is a useful diagnostic distinction:

```text
UI loaded != OS control plane healthy
```

## First Gadget: Slides

Created a Slides Gadget from the built-in Blueprint and asked the agent to generate an experimental Forklight concept deck.

The agent reported that it:

1. inspected `server.js` and `client.js`
2. learned the deck/block data model
3. generated SVG-heavy slide content programmatically
4. wrote the complete deck through Gadget RPC
5. read the deck back for validation

The important architectural observation was that the agent modified **application data via the Gadget API**, rather than necessarily rewriting the Gadget implementation for every content change.

## Cost observation

One Slides trajectory consumed approximately:

- ~343k input tokens
- ~53k output tokens
- ~55k Workers AI neurons
- roughly $0.50 billable usage after the daily free neuron allowance

This demonstrates the amplification between a short user request and a multi-step agent trajectory.

## Model compatibility experiments

### GLM 5.2

Worked successfully as a built-in model.

### Qwen3 30B A3B FP8

Custom model:

```text
@cf/qwen/qwen3-30b-a3b-fp8
```

Failed even on `hello`.

Observed reason: Cloudflare OS reserves a 32,768-token Workers AI output budget while this model has a 32,768-token total context window, leaving no input budget.

Lesson:

```text
provider support != runtime compatibility
```

Context-window policy is part of the model adapter.

### GPT-OSS 20B

Custom model:

```text
@cf/openai/gpt-oss-20b
```

Failed with HTTP 400 schema validation during agent conversation.

Observed errors included structured `messages[].content` values not matching the endpoint schema.

Lesson: function-calling capability on a model card is insufficient to guarantee compatibility with a specific agent runtime. Message representation, tool-call round trips, API dialect, reasoning representation, and model adapters all matter.

## Main takeaways

1. Cloudflare OS is more interesting as a composition of runtime primitives than as a chat UI.
2. Capability security and Gadget isolation are central design decisions.
3. A healthy model provider does not imply the agent runtime can use every model from that provider.
4. Agent workloads can multiply token usage by orders of magnitude relative to the original prompt.
5. The persistent RPC/control channel should be checked before debugging higher layers such as model inference.
